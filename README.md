# Question Modal 问卷弹窗

给 [QwenPaw](https://github.com/agentscope-ai/QwenPaw) 智能体用的**对话内阻塞式问卷**工具。

当智能体需要你**在方案间做选择、确认范围、或拍板一个阻断项**时，它会调用 `question_modal` 工具。
不再把「甲 / 乙 / 丙」写成正文段落等你手打回复，而是**在对话里直接渲染出一张可点选的多页问卷卡**，
暂停等待，拿到你的结构化答案后继续推理。

## 一句话价值

**把「选择题」从打字变成点选。** 纯文字选项无法点选、容易漏答、格式易被模型写歪；问卷卡把选项变成按钮，
一次问清、结构回传、无需复述。

## 功能点

### 题型

| 类型 | 说明 |
| --- | --- |
| `single` | 单选（点选即替换） |
| `multi` | 多选，**回传为数组**；二选一场景请用 `single` |
| `text` | 自由问答输入 |

- 每道选择题都自带一个**「其他」文本框**，可填自定义答案。
- 每道题的「其他」框下方可**添加附件**（回形针按钮），支持多选文件。
- 问卷最后一页有独立的**「其他意见」**输入框（同样可添加附件），与题目同级。
- 选项按 `1. 2. 3.` **自动编号**（仅卡片显示，方便口述定位；**回传仍是选项原文**，
  不影响推荐匹配与「只用推荐」）；「其他」为插件入口，不参与编号。
- 模型若**漏写某题题干**，卡片会兜底显示「第 N 题」而非空白（工具描述已硬性要求
  每题必须带 `title`，兜底只是最后一道防线）。

### 推荐标记（`recommended`）

出题时可以给选择题标注推荐项，被推荐的选项**左侧**会显示一枚「AI 推荐」矩形徽章：

```json
{"type": "single", "title": "用哪个方案？", "options": ["甲", "乙"], "recommended": "乙"}
{"type": "multi",  "title": "包含哪些模块？", "options": ["A", "B", "C"], "recommended": ["A", "C"]}
```

- 值是**选项原文**（label 或 value 均可匹配），多选用数组。
- 徽章在任何模式下都显示，仅作提示，不影响作答；推荐行**不加底色**，
  避免与「已选中」的视觉信号混淆——是否选中只由勾选态表达。
- 工具描述把 `recommended` 定为**默认必做**：每道选择题都应标注推荐项，
  只有确实无法取舍时才留空（不标注就没有徽章，也没有「只用推荐」的输入）。
- ⚠️ `options` 必须保持**纯字符串数组**——推荐标记写在题目的 `recommended` 字段上，
  不要塞进 `options` 元素里（后端会 `join(options)`，对象会报错）。

### 三种驱动模式

卡片顶部开关，按卡片独立记忆，切到下一份问卷互不影响：

| 模式 | 行为 | 是否调用模型 |
| --- | --- | --- |
| **自动分析** | 逐题分析 → 自动填入推荐 → 翻页 → 末页自动提交 | 是，每题一次 |
| **只用推荐** | 采纳 `recommended` 标注（无则回退历史分析缓存）→ 自动填入 → 翻页 → 提交 | **否，零请求** |
| **人工** | 由你手动作答 | 仅在你点「开始分析」时 |

两种自动模式都可点「⏸ 停止」随时接管，再点「▶ 继续」恢复自驱。
「只用推荐」下若某题既无推荐也无缓存，该题会被跳过（提交时标 `skipped: true`），流程不会卡住。

### AI 分析（题级）

- 分析针对**当前展示的题**，每题独立结果；切题即分析，不整卷预跑。
- 基础上下文 = 本卷当前题之前已答题；勾选「携带上下文」再叠加上一份问卷
  （题目/答案/AI 结论）与会话历史。
- 已完成的分析再次查看**不重跑**；顶部「重新分析」只重跑当题并沿用上次设置。
- 结果按题存储，重跑覆盖旧值，不堆积历史。

### 提示词模板

- 「系统提示词 + 用户提示词」可保存为模板，模板库**全局共享**（新建/编辑/删除）。
- 内置模板「默认六步思维链」可编辑但不可删，删除自定义覆盖即回滚到出厂文案。
- 模板按卡片独立选择；保存时校验 JSON 返回契约（须保留 `choice` / `reasoning`），
  防止改坏导致分析恒为空。

### 附件

- 附件走**宿主的官方上传端点**（与输入框同一个），因此**大小上限与类型规则和输入框完全一致**：
  上限由 `upload_max_size_mb` 决定（未配置即不限制），类型不做白名单（仅图片做完整性校验）。
- 附件随答案一起回传，模型在「【用户提交的问卷答案】」里会看到
  `（附件：设计稿.pdf（2.0 KB））` 这样的可读条目，JSON 里带 `url / file_name / size`。

### 条件题（`showIf`）

后一题依赖前一题答案时，用 `showIf` 做动态联动——选中前置选项后该题才出现：

```json
{"q0": ["用 pm 设计器做表单"]}
```

- 键可写序号（`q0`/`q1`）或题目原文；值支持字符串或数组。
- 数组内多值 = **OR**（任一命中即显示）；多个键 = **AND**（全部成立才显示）。
- 前置加 `=` 表示精确匹配（默认是宽松包含匹配）。
- 未被选中的分支会自动跳过：**进度分母 = 可见题数**，跳过的不计入，隐藏题的答案不会回传。

### 严格作答闸门（逐题强制表态）

人工模式下，**未作答的题不会被静默跳过**：

- 当前题既没选、也没显式跳过时，点「下一步」或「提交」**一律无效**——卡片内出现
  一条常驻红条，写明第几题未选、以及可用的按钮指引（不弹瞬时 toast，不留内部术语）。
- 想跳过某题必须点该页的**「跳过本题」**（显式表态），或在末页点**「跳过并提交」**。
- 因此「答了一半却整卷交上去」从界面上不可能发生；回传里也不会再出现
  空白值被误读成「跳过」的歧义——未作答与主动跳过是两种不同记录。

每次拦截都会向后端记一条审计（`gate_blocks.json`，保留最近 200 条），
便于排查「到底拦没拦」这类无法从提交结果反推的问题。

### 题级计时提示（停留超时提醒）

作答过程中，**每道题独立计时**（默认阈值 60 秒）：

- 停留满阈值才提示一次，且**计时停在该值**——界面上没有跳动的秒数，
  作答期间零每秒重渲染（一个单次定时器，到点只渲染一次）。
- **切题即清零**：点「下一步」或退回「上一步」都重新开始计；「其他意见」末页同样计时。
- 提示位于卡片下方，与故障自救横幅共用一条：写明「本题已超过 60s，可直接跳过或继续作答」，
  右侧始终保留**「释放本次问卷」**按钮（会话被问卷阻塞时唯一的逃生口）。
- **只提醒、不强制**：不会自动跳题、不会自动填答案，与「严格作答闸门」互不干扰。
- 整卷级计时不再打扰：问卷打开后不会因为「总共过了 30 秒」而弹提示。

计时起点持久化到卡片状态（`slowAt` + `slowStep`），因此宿主重挂载卡片后按**剩余时间**
续算——不会因为你滚了一下页面就白白多等一分钟。

### 提交后的等待提示（后台计时）

提交或跳过之后，卡片给出一行状态提示。它的判定与呈现刻意做到**不干扰模型输出**：

- **不挂任何 DOM 观察者、不每秒重渲染**：改用低频后台轮询判断「卡片之外是否已有模型
  新输出」，一旦判定模型已恢复即停表退休；等待期间页面渲染次数为 0。
  （早期版本把观察者挂满 `body`，流式输出期高频全量扫描会抢占主线程、反而拖慢绘制。）
- **越阈值才升级文案**：短时间内只显示一句「已提交，模型处理中」；超过约 20 秒才追加
  释放指引（此时多半是模型限流/报错），并提示「发新消息若报 `A task is already running`
  可点右侧『释放阻塞』」。
- **历史卡片不再挂自救按钮**：只有本实例刚提交的那张卡才提供释放入口，翻旧对话不会
  出现一排无关的自救按钮。
- 已跳过整卷的卡片不会谎报「模型处理中」。

### 跳过语义（三档，互不混淆）

| 操作 | 行为 |
| --- | --- |
| **跳过本题** | 纯本地标记，不发后端；回传里显式记录 `（用户跳过本题）`，继续答下一题 |
| **跳过问卷** | 收起成一行摘要「✓ 已跳过问卷」，可展开；整体返回 `{"skipped": true}` |
| **取消** | 前端自救出口，解开阻塞、释放会话 |

### 答不丢、错不错配

- 每张卡片按 `tool_call_id` 精确解析归属，**刷新页面或陈旧请求不会绑错问卷**。
- 请求句柄持久化到 `localStorage`，另有心跳自愈 + 自救出口，卡住时可解开。
- **进度与答案抗重挂载**：宿主消息列表是虚拟滚动，卡片滚出视口会被卸载重挂载。
  本轮把整个交互状态（当前题号 / 已选项 / 已填文本 / 附件）持久化到
  `localStorage`（键 `qm:v1:state:<tool_call_id>`），重挂载后原样恢复——
  **不会再把「答了一半」的问卷打回第 1 题、也不会把「已答完」的问卷重新变成待答**。
- 结果缓存与服务端 pending 均长寿（GC 时限 365 天），**过夜问卷次日提交不会 404**。
- **历史卡片答案可恢复**：会话变长后宿主会把旧工具结果折叠成占位符，卡片会自动按
  `tool_call_id` 从后端取回真实答案并正常展示（结果缓存**落盘持久化**，插件重启也不丢）；
  万一确实取不回，会显示中文提示而不会把占位符当答案。

### 原生渲染

走宿主官方 `chat.toolRender(pluginId, "question_modal", Component)` 通道——问卷卡渲染在
**宿主审批卡的同一区域**，延迟≈0，刷新后仍在。视觉上逐项对齐宿主的审批卡规范
（卡片边框 / 圆角 / 主题色 / 选项高亮 / 按钮规格）。

## 回传格式

```json
{
  "answers": {
    "q0": {"type": "single", "value": "选项 A", "other": "", "skipped": false,
           "attachments": [{"url": "/media/xx_doc.pdf", "file_name": "doc.pdf", "size": 2048}]},
    "q1": {"type": "multi",  "value": ["X", "Y"], "other": "", "skipped": false},
    "q2": {"type": "text",   "value": "自由输入", "other": ""}
  },
  "other": "",
  "attachments": [{"url": "/media/yy.png", "file_name": "yy.png", "size": 1024000}],
  "skipped": false
}
```

- `answers[*].attachments` = 该题「其他」框下的附件；顶层 `attachments` = 末页「其他意见」的附件。
- 跳过整份问卷：`{"skipped": true}`
- 跳过某一题：该题带 `skipped: true`，问卷继续。

## 亮点

1. **交互有效性**：正文罗列「甲/乙/丙」用户点不了，模型还常把多选写成单选题。问卷卡把选择变成点选，回传结构化数据——这是与「文字选项」的本质区别。
2. **条件题联动**：`showIf` 让问卷像真表单一样分支，进度分母自动跟随可见题数，隐藏答案不污染回传。
3. **多选可回传数组**：一道题勾多项，结果直接是数组，模型不会再把它拆成多道「是/否」。
4. **抗刷新、抗错配**：按 `tool_call_id` 解析 + 本地句柄持久化 + 心跳自愈，刷新、网络抖动、陈旧请求都不会绑错或丢失。
5. **抗虚拟滚动**：交互状态（题号/答案/附件）持久化到 `localStorage`，卡片被卸载重挂载后进度与作答原地恢复。
6. **可自救**：阻塞期间会话会锁死（宿主机机制），因此内置「释放/取消」出口，避免永久卡住。
7. **原生外观**：用宿主官方扩展点注册，位置与样式对齐宿主的审批卡，不是浮层补丁。
8. **附件与输入框同源**：附件走宿主同一上传端点，大小/类型限制与输入框天然一致，无需额外配置。
9. **零运行依赖**：不需要任何第三方 Python 或 npm 包。
10. **对模型的行为引导内置**：工具描述内含**硬性规则**（任何需要用户在候选项间选择的场景都必须调用本工具，
    严禁正文罗列选项）与**判定口诀**（正准备写「1. … 2. …」或以「是否…？」结尾就该改用本工具），
    另有 multi / showIf / 附件 / **recommended 推荐标记** 的场景说明。
11. **三种驱动模式**：自动分析（逐题调模型）、只用推荐（零请求，直接用出题时的标注）、人工。
    自动化是**无人值守**的——填答案、翻页、末页提交一条龙，随时可「停止」接管。
12. **题级分析而非整卷**：每题独立分析、独立结果，切题即算，尊重题目之间的前后联动；
    已完成的不重跑，重跑只留最新。
13. **提示词可自定义**：分析用的系统/用户提示词可存为模板、全局共享、按卡片选用；
    保存时校验 JSON 返回契约，改坏会被拒绝而不是静默失效。
14. **逐题强制表态**：未作答的题点「下一步」即被拦并给出常驻指引，跳过必须显式点击——
    杜绝「一路下一步把空白题静默跳过」，也让「未作答」与「主动跳过」在回传中可区分。
15. **可取证的拦截与收敛**：闸门拒绝、问卷失效等「不发请求」的事件都会落盘审计，
    配合卡片自带的构建指纹，可区分「逻辑没生效」与「浏览器仍在跑旧包」——
    这两类问题的现场表现完全相同，没有痕迹便无法定性。
16. **题级计时、整卷不打扰**：停留超时按**每道题**计算（默认 60 秒），切题即清零、
    末页同样计时；只提示一次、不跳秒、不强制跳题。问卷打开后不会再因为「总共过了
    三十秒」弹出提示，避免频繁提醒造成心理负担。
17. **提交后的等待不占用页面**：等待提示改为后台低频轮询判定「模型是否已恢复输出」，
    不再每秒重渲染、不挂任何 DOM 观察者，因此不会拖慢模型流式绘制；越阈值才升级
    为带释放指引的文案，历史已作答卡片不再显示自救按钮。
18. **写盘不阻塞放行、并发不损坏缓存**：唤醒 agent 排在记账之前；结果缓存与决策记录
    改为后台线程落盘，并修掉固定 `.tmp` 文件名在并发写时互相截断的隐患
    （一旦发生，插件重启会解析失败、丢掉整份历史答案缓存）。
19. **选项自动编号 + 缺题干兜底**：选项行按 `1. 2. 3.` 显示（回传仍是选项原文，
    推荐匹配零影响）；模型漏写题干时兜底「第 N 题」，且工具描述已硬性要求每题必带
    `title`——显示兜底与源头要求双保险。

## 环境要求

- QwenPaw `>= 2.0.0, < 2.3.0`（已在 2.2.x 验证）
- 运行期无第三方 Python / npm 依赖

## 安装

控制台 → 插件 → 安装，或：

```bash
qwenpaw plugin install question-modal-2.2.0.zip
```

插件支持**热加载**。**安装后请硬刷新浏览器（Ctrl+Shift+R）**——前端 bundle 在页面加载时注入，
已打开的页面不会自动重新加载新渲染器。

⚠️ 注意：安装（或重装）后，宿主会在每个智能体配置里**以「禁用」状态**创建该工具条目。
请为需要使用它的智能体手动启用 `question_modal`
（设置 → 工具，或 `agent.json → tools.builtin_tools.question_modal.enabled`）。

## 行为引导

工具描述会告诉模型何时使用。若某个智能体仍用文字罗列选项而不弹问卷，
可在该智能体的 `SOUL.md` 里补一句：

> 当你需要用户做选择、二选一/多选一、裁定阻断项、确认范围时，必须调用 `question_modal` 工具以问卷形式收集答案，
> 禁止在回复正文里罗列选项后停下等待手打回复——纯文字选项用户无法点选，属于无效交互。
