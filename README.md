# Question Modal 问卷弹窗

把「让用户做选择题」从打字变成点选的对话内阻塞式问卷工具。

智能体需要你拍板时调用 `question_modal`，对话里弹出可点选的多页问卷卡并暂停等待，
拿到结构化答案后继续推理。

| | 纯文字选项 | 本插件 |
| --- | --- | --- |
| 作答方式 | 打字复述 | 点选按钮 |
| 漏答 | 容易发生 | 闸门拦截 |
| 回传 | 需解析自然语言 | 结构化 JSON |
| 附件 | 无 | 支持 |

## 运行模式

核心特性：**自动分析**与**只用推荐**两种模式的推进逻辑运行在**服务端**，
不是浏览器——**不依赖页面**。页面只是显示器。

这意味着：

- **关掉标签页、关掉浏览器、换设备，问卷照样走完并提交。**
- 同一条会话同时开多个页面，也只有一个推进者（后端），
  不会出现两个页面互相抢着答题。
- 只有**人工**模式需要你打开页面手动点选——因为它本来就在等人。

| 模式 | 推进位置 | 需要你操作 | 调用模型 | 关掉页面后 |
| --- | --- | --- | --- | --- |
| 自动分析 | 服务端 | 不需要 | 是，每题一次 | 继续推进直到提交 |
| 只用推荐 | 服务端 | 不需要 | 否，零请求 | 继续推进直到提交 |
| 人工 | 服务端只存档，等你操作 | 需要 | 仅在你点「开始分析」时 | 保持等待，重开页面接着答 |

前端只在一种情况下接管推进：与服务端的长连接断开时（降级兜底），
一旦连接恢复就让回给服务端，避免两边同时推进导致跳题。

## 安装与启用

在控制台的插件页安装，或执行：

```bash
qwenpaw plugin install question-modal-2.4.3.zip
```

安装（含重装）后，宿主会以**禁用**状态创建工具条目，需为要使用它的智能体手动启用
`question_modal`：

- 界面路径：设置中的「工具」页
- 或直接改 `agent.json` 里的 `tools.builtin_tools.question_modal.enabled`

## 题目契约

模型调用 `question_modal` 时传入的题目结构。字段写错会导致卡片渲染异常或答案丢失。

### 基本结构

```json
{
  "title": "问卷标题",
  "questions": [
    {"type": "single", "title": "用哪个方案？", "options": ["甲", "乙"], "recommended": "乙"},
    {"type": "multi",  "title": "包含哪些模块？", "options": ["A", "B", "C"]},
    {"type": "text",   "title": "补充说明"}
  ]
}
```

### 三种题型

| 类型 | 说明 |
| --- | --- |
| `single` | 单选，点选即替换 |
| `multi` | 多选，回传为数组。二选一场景请用 `single` |
| `text` | 自由问答输入 |

选项会自动编号，仅便于口述定位，回传的仍是选项原文。

`options` 必须保持纯字符串数组。任何附加信息都应放在题目级字段上，
不要塞进 `options` 元素里。

### 推荐标记

用 `recommended` 给选择题标注推荐项，被推荐选项左侧会显示「AI 推荐」徽章。

值是选项原文；多选传数组，如 `"recommended": ["A", "C"]`。
徽章在任何模式下都显示，仅作提示，不影响作答。

### 条件显示

后一题依赖前一题答案时，用 `showIf` 做联动，选中前置选项后该题才出现：

```json
{"q0": ["用 pm 设计器做表单"]}
```

键可写序号（`q0`/`q1`）或题目原文；值支持字符串或数组，数组表示任一命中即显示。

未被选中的分支会自动跳过：进度分母按可见题数计算，隐藏题的答案不会回传。

## 作答界面

### 严格作答闸门

人工模式下，未作答的题不会被静默跳过：

- 当前题既没选、也没显式跳过时，点「下一步」或「提交」一律无效，
  卡片内会提示第几题未选以及可用的按钮。
- 想跳过必须显式点击「跳过本题」，或在末页点「跳过并提交」。

因此「答了一半却整卷交上去」从界面上不可能发生。

### 阻塞自救：会话卡住时的出口

问卷是**阻塞式**的——智能体发起后会暂停等你作答。正常情况下你答完就自动放行。
但在个别异常路径下，卡片可能显示「已完成」，会话却仍被锁住：发新消息报
`A task is already running for this chat`，而你无处可点。

典型成因（都由后端记录与运行态的错位引起，不是你的操作问题）：

- 问卷服务重启导致等待被中断，卡片与后端记录脱节
- 记录已失效或被清理，卡片仍停在作答/已完成视图
- 提交完成但底层等待未被真正放行

这种情况点卡片上的「**释放阻塞**」按钮：

| 结果提示 | 含义 |
| --- | --- |
| 已释放本次问卷的阻塞，会话可继续 | 插件端放行成功，正常继续对话 |
| 已直接终止本次运行，会话可继续对话 | 插件端记录已不可达，升级为终止本次运行；本次回答不会回传给模型 |
| 后端已无这条记录的阻塞，无需释放 | 本来就没人锁着；若仍报错，点宿主输入框旁的「停止」 |

设计上的三点克制：

- **只在你显式点击时执行**，正常健康的问卷绝不会被后台悄悄终止。
- **按钮常驻已完成态**。正因为「卡片显示完成」不等于「会话真的被放行」，
  这个出口不能随完成状态一起消失。
- 历史只读卡片不显示该按钮（本页并未真正等待过，无需自救）。

### 其他答案与附件

- 每道选择题自带「其他」文本框，可填自定义答案。
- 问卷末页另有独立的「其他意见」输入框。
- 「其他」框与末页均可添加附件，走宿主同一上传端点，大小与类型规则和对话框一致。

### 设置面板

工具栏的问卷设置入口打开居中弹窗，两层作用域：

| 作用域 | 可改项 | 生效范围 |
| --- | --- | --- |
| 会话模式 | 模式 / 模型 / 提示词模板 / 携带上下文 / 并行分析 | 仅本会话 |
| 默认模式 | 同类设置，加人工模式提醒 / 单题分析超时 / 等待提示阈值等 | 未设会话覆盖的会话 |

生效优先级：本会话改过该项就用会话覆盖，否则用全局默认，都没设才用内建默认。
卡片与设置面板读的是同一份配置，两处显示始终一致。

## 回传格式

```json
{
  "answers": {
    "q0": {"type": "single", "value": "选项 A", "other": "", "skipped": false,
           "attachments": [{"url": "/media/xx_doc.pdf", "file_name": "doc.pdf", "size": 2048}]},
    "q1": {"type": "multi",  "value": ["X", "Y"], "other": "", "skipped": false},
    "q2": {"type": "text",   "value": "自由输入", "other": ""}
  },
  "other": "",
  "attachments": [{"url": "/media/yy.png", "file_name": "yy.png", "size": 1024000}],
  "skipped": false
}
```

- `answers[*].attachments` 是该题「其他」框下的附件。
- 顶层 `attachments` 是末页「其他意见」的附件。
- 跳过整份问卷时回传 `{"skipped": true}`。
- 跳过某一题时该题带 `skipped: true`，问卷继续。

## 注意事项

### QwenPaw 2.3.x 需关闭代码模式

2.3.x 上若开着「代码模式（Code Mode）」，问卷卡片可能无法正常渲染或交互，
请在运行配置中手动关闭。

### 模型不主动弹问卷时

若智能体仍用文字罗列选项，而你希望它弹卡片，可在其 `SOUL.md` 中补充：

> 需要用户做选择、二选一 / 多选一、裁定阻断项或确认范围时，必须调用 `question_modal`
> 收集答案，禁止在正文罗列选项后等待手打回复。

## 环境要求

- QwenPaw `>= 2.0.0`，已在 2.2.x 验证。2.3.x 需先关闭代码模式，见上文注意事项。
- 运行期无第三方 Python 或 npm 依赖。
